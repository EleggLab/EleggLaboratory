# Foundation Prompts for Vibe Coding (Reference Only)

> 목적: 아래 프롬프트는 **명령 템플릿이 아니라 참고 자료**예여.  
> 사용 방식은 에이전트/모델이 상황에 맞게 선택하도록 남겨두세여.

---

## 1) Problem Framing Prompt
"""
문제를 한 문장으로 정의하고,
사용자/비즈니스/기술 관점에서 각각 왜 중요한지 3줄 이내로 정리해줘.
그리고 이번 작업에서 절대 하지 말아야 할 것(Non-goal) 3개를 적어줘.
"""

## 2) Scope Cutting Prompt
"""
요구사항을 Must/Should/Could로 나눠줘.
이번 턴에서 완료 가능한 최소 범위(MVP)를 먼저 제안하고,
나머지는 다음 스프린트 백로그로 분리해줘.
"""

## 3) Architecture Sketch Prompt
"""
현재 요구사항 기준으로 가장 단순한 구조를 제안해줘.
컴포넌트 목록, 데이터 흐름, 외부 의존성, 실패 지점을 짧게 정리하고,
대안 1개와 트레이드오프를 함께 제시해줘.
"""

## 4) Implementation Plan Prompt
"""
구현 순서를 5단계 이내로 제안해줘.
각 단계마다 변경 파일, 예상 리스크, 검증 방법을 붙여줘.
작업 단위는 커밋 가능한 크기로 쪼개줘.
"""

## 5) Test Design Prompt
"""
이 기능에서 깨지기 쉬운 경계조건을 먼저 찾고,
단위/통합/회귀 테스트로 분류해 테스트 케이스를 제안해줘.
실패 재현 시나리오도 포함해줘.
"""

## 6) Debugging Prompt
"""
증상을 바탕으로 가능한 원인을 우선순위로 정렬해줘.
각 원인별 확인 실험(로그/재현/비교)을 제안하고,
가장 빠르게 원인을 배제할 수 있는 순서로 진행계획을 작성해줘.
"""

## 7) Refactoring Prompt
"""
현재 코드에서 중복/결합도/가독성 문제를 찾고,
동작 변경 없이 개선 가능한 리팩터링 후보를 제시해줘.
리스크가 큰 변경은 별도 브랜치 전략으로 분리해줘.
"""

## 8) Security Sanity Prompt
"""
입력 검증, 인증/권한, 비밀정보 처리, 의존성 취약점 관점에서
빠른 보안 점검 항목을 체크리스트로 제시해줘.
이번 배포에서 필수 차단 항목을 명확히 표시해줘.
"""

## 9) Docs & Handover Prompt
"""
신규 팀원이 10분 안에 이해할 수 있도록
실행 방법, 주요 결정, 자주 깨지는 포인트, 롤백 방법을 문서화해줘.
"""

## 10) Retrospective Prompt
"""
이번 작업에서 잘한 점/아쉬운 점/다음에 자동화할 점을 정리해줘.
반복 가능한 교훈을 팀 규칙(체크리스트/템플릿)으로 바꿔 제안해줘.
"""

---

## 사용 가이드
- 이 문서는 **레퍼런스 카드 모음**이예여.
- 프롬프트를 그대로 강제하지 말고, 모델이 상황에 맞게 조합하도록 두세여.
- 프로젝트 특성에 맞게 도메인 단어만 바꿔 재사용하면 효율이 높아져여.
