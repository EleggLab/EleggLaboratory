# Pattern Adoption Policy

## 목적
리서치 결과를 starter에 무분별하게 복붙하지 않고, 재사용 가능한 형태로 흡수.

## 프로세스
1. 후보 선별: `starter-adoption-candidates.md`
2. 배치 생성: `starter/backlog.md`
3. 반영: prompts/scripts/checklists/docs 중 1개 영역씩
4. 검증: `starter/scripts/verify.sh` + `starter/scripts/report.sh`
5. 기록: 반영 커밋 + 패턴 노트 업데이트

## 거절 기준
- 설명은 화려한데 재현 절차가 없는 자료
- 프로젝트 성격이 지나치게 특수한 경우
- 보안/라이선스 리스크가 큰 경우
