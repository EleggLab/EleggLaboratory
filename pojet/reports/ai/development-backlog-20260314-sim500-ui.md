## 이미지 기준 주요 문제
1. 좌측 인물 패널이 본문보다 시각적으로 강하다.
- 첫 화면에서 가장 먼저 눈에 들어오는 것은 인물 초상과 상태 배지다.
- 스토리 본문이 메인이라는 목표와 충돌한다.

2. 상단 운영 버튼이 너무 많다.
- 일시정지, 저장, 불러오기, 기록 보관소, 연대기 정리, 설정, 새 삶 시작이 한 줄에 모두 있다.
- 제목 영역과 경쟁한다.

3. 상황 설명 박스가 과하게 크다.
- 실제 텍스트는 1~2줄인데 카드 높이가 커서 빈 공간이 많다.
- 본문 카드보다 비효율적으로 면적을 먹는다.

4. 본문 스토리 카드가 넓지만 읽기 리듬은 약하다.
- 줄 길이가 길고, 문단 간 호흡 차이가 적다.
- 소설 읽는 느낌보다 설명 카드 느낌이 더 강하다.

5. 선택지 카드가 본문 아래에서 너무 또렷하게 튄다.
- 선택지는 중요하지만, 현재는 본문을 읽기 전에 시선을 빼앗는다.
- 버튼 색 대비가 본문 카드보다 세다.

6. 우측 세로 탭과 좌측 정보 패널이 동시에 살아 있어서 중앙 집중을 깨뜨린다.
- 우측 `보조 정보` 세로 탭은 접혀 있어도 계속 눈에 보인다.
- 좌우 모두 보조 영역이 살아 있어서 중앙 집중력이 분산된다.

## 시뮬레이션 기준 주요 문제
1. 초반 6턴 수준에서는 오리진 차이가 보이지만, 구조가 빨리 비슷해진다.
- category 분포는 다르지만, `social -> relationship/market/faction/legacy` 식 골격이 반복된다.
- 오프닝 이후 중반 진입 전 단계에서 체감상 비슷해질 위험이 있다.

2. 훅 문장은 통과 수준이지만 아직 체감 반복이 남는다.
- repeatedHookRate 0.1097은 실패 수준은 아니지만, 플레이 감각상 반복을 느낄 수 있는 구간이다.
- 특히 `공기와 거리감이 먼저 바뀐다` 같은 계열 문장이 자주 남는다.

3. 같은 의미의 선택이 다른 장면에서도 비슷한 라벨로 돌아온다.
- 의미 중복은 줄었지만, 플레이어 관점에서는 `정면 돌파`, `완만한 처리`, `빠져나가기` 류가 반복된다.
- 선택 결과의 차이가 표면 문구에 더 드러나야 한다.

4. 오프닝 후 고정 장면 묶음이 더 필요하다.
- 지금은 오프닝 감도는 생겼지만, 첫 10~20턴을 떠받치는 전용 씬 풀이 부족하다.
- 그래서 중반 생성 로직이 너무 빨리 개입한다.

## 추가 개발 목록

### P1. 메인 화면을 `스토리 단일 집중형`으로 재배치
- 좌측 인물 패널 기본 폭을 줄이거나 접이식으로 변경
- 우측 `보조 정보` 세로 탭은 완전히 숨기고, 필요 시만 호출
- 상단 운영 버튼은 `메뉴` 하나로 접어 넣고 기본 노출은 `저장`, `설정`, `새 삶 시작` 정도로 축소
- 상황 설명 박스는 한 줄 요약 높이로 줄이고, 본문 스토리 카드 높이를 더 늘릴 것

### P2. 본문 타이포와 문단 리듬 강화
- 본문 최대 줄 길이를 줄여 가독성을 높일 것
- 문단 첫 줄 강조, 문단 간 여백 차등, 장면 전환선 추가
- 상황 설명과 스토리의 시각 계층 차이를 더 명확히 할 것
- 본문 카드 내부 여백을 더 주고, 선택지 카드와 색 대비를 덜 경쟁적으로 조정할 것

### P3. 초반 10~20턴 전용 고정 장면 세트 확장
- 현재 6개 오리진 각각 최소 12~20개 고정 장면 세트 필요
- 오프닝 직후 3~5턴은 완전 고정 시퀀스, 6~12턴은 반고정 시퀀스로 운영
- 생성기는 초반을 쓰지 말고, 전용 장면 세트를 소진한 뒤에만 개입

### P4. 중반 생성 로직에 `구조 다양화 레이어` 추가
- 현재는 카테고리만 달라지고 흐름 뼈대가 비슷하다
- 카테고리 이전에 `장면 압력 유형`을 넣어야 한다
  - 협상형
  - 추적형
  - 회피형
  - 유혹형
  - 은폐형
  - 지배형
- 같은 카테고리라도 압력 유형이 다르면 전개 구조가 달라지게 해야 한다

### P5. 훅 문장 전용 풀 확장과 금지 규칙 추가
- `공기`, `거리감`, `기류`, `온도` 계열의 상투 표현 빈도를 낮춰야 한다
- 최근 N턴 내 사용한 훅 어휘를 재사용 금지하는 캐시를 추가
- 오리진별 훅 풀, 장소별 훅 풀, 갈등 유형별 훅 풀을 분리

### P6. 선택지 표면 문구를 `행동 방식 + 기대 효과` 중심으로 재작성
- 지금은 동사 자체는 다르지만, 체감상 같은 선택지가 반복된다
- 선택지는 아래 형태로 고정하는 것이 좋다
  - 무엇을 어떻게 할지
  - 그 선택이 노리는 단기 효과
- 예: `정면으로 밀어붙인다`보다 `먼저 말을 끊고 주도권을 잡는다`가 더 좋다

### P7. 선택 직후 결과 문장의 손익 표면화 강화
- 플레이어가 `무엇을 얻고 무엇을 잃었는지`를 서사로 즉시 느끼게 해야 한다
- 수치 노출 없이도 손익이 보이도록 반응 문장을 표준화
- 예: 신뢰가 줄었으면 표정/거리/침묵으로, 명성이 올랐으면 주변 반응/소문/호칭 변화로 보여주기

### P8. 좌측 패널 정보 축소
- 현재 관계의 온도, 정체성 축, 배지까지 한 번에 보여서 과밀하다
- 기본 표시를 3~4개 핵심 정보만 남기고 나머지는 접기
- 메인 플레이 중에는 `이름`, `종족`, `오리진`, 핵심 감정 상태만 기본 노출

### P9. 깨진 문자열 차단을 위한 최종 방화벽 추가
- 현재 게임 화면은 많이 안정됐지만, 보고서/보조 경로에는 여전히 인코딩 잔재가 있다
- 런타임 표시 전에 `mojibake`, 대체문자, 괄호형 메타 설명을 한 번 더 걸러내는 최종 필터 필요
- 저장 라이브러리 publish 전 품질 게이트도 더 엄격하게 해야 한다

### P10. 플레이 로그/기록 보관소를 메인 화면에서 완전히 분리
- 플레이 화면은 스토리와 선택지만 남기고, 기록은 별도 모달 또는 별도 보기로 유지
- 현재도 분리된 편이지만 상단 버튼과 용어가 아직 메인 플레이를 방해한다

### P11. 자동 QA 파이프라인 확장
- 현재 자연성/차별화 감사는 유효하지만, UI 감시는 없다
- 추가로 필요:
  - 스크린샷 비교 기반 레이아웃 회귀 테스트
  - 본문/선택지 OCR 길이 검사
  - 너무 짧은/너무 긴 카드 감지
  - 가로폭 대비 줄 길이 경고

### P12. 보고서 생성기 자체 안정화
- 차별화 감사 JSON에서 문자열 인코딩/escape 안정성이 낮다
- 게임 본체 우선순위는 아니지만, 개발 과정에서는 꽤 방해가 된다
- 감사 리포트는 반드시 UTF-8 정상 JSON으로 떨어지게 보강 필요
