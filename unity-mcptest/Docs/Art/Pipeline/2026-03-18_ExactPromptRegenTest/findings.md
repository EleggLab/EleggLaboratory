# Exact Prompt Regen Test Findings

## 목적
- 사용자가 제공한 프롬프트형 파일명 프롬프트를 거의 그대로 사용해서 API 재생성
- 결과가 원본과 얼마나 비슷한지 확인
- 차이가 크면 `프롬프트 해석 문제`보다 `API/모델/설정 차이` 가능성을 우선 의심

## 실행 방식
- 입력: `SelectedForExpansion` 안의 프롬프트형 파일명 이미지 27장
- 프롬프트: 파일명 stem 그대로 사용
- seed: 파일명 뒤의 `s-숫자`를 추출해서 동일하게 사용
- negative prompt: 없음
- 크기: 원본 이미지 크기 그대로 사용
- 자동 생성 모델: `nai-diffusion-3`

## 관찰 결과
- 원본 스타일과 가까운 재현은 거의 나오지 않음
- 빈번한 실패 패턴:
  - 다른 화풍으로 튐
  - 스티커/마스코트처럼 변형됨
  - 배경색이 붙거나 장식 요소가 생김
  - 1인 전신이 아니라 작은 캐릭터/시트처럼 나옴
  - 같은 prompt여도 선 굵기와 비율이 완전히 달라짐

## 대표 비교
- `score_9, score_8_up, masterpiece, (slight chibi_0.8), (smaller head_1.3), bold l s-3981419444`
  - 원본: 녹색 드래곤 계열 소년, 깨끗한 굵은 선, 전신, 흰 배경
  - 재생성: 노란 SD 캐릭터로 변형, 구도와 종족 자체가 달라짐
- `score_9, score_8_up, masterpiece, __full body, standing, (feet_1.3)__, chibi sty s-1631311782`
  - 원본: 모험가 전신, 카드용 판타지 스타일
  - 재생성: 아주 단순한 SD 마스코트형으로 축소

## 1차 결론
- 이번 차이는 `내가 프롬프트를 바꿔서` 생긴 문제가 아님
- 사용자 제공 프롬프트를 거의 그대로 넣어도 원본 분위기를 재현하지 못했음
- 따라서 현재 자동 API 결과만으로는 사용자가 원하는 스타일 복제가 어렵다는 판단이 맞음

## 가능한 원인
- 원본 이미지가 `V4.5 웹 UI`의 최신 기능으로 생성됐을 가능성
- `Vibe Transfer` 또는 `Character Reference` 같은 레퍼런스 기능 개입
- 원본에 사용된 세부 설정이 파일명에 다 남아있지 않음
- 현재 자동 검증 모델이 `nai-diffusion-3`이며, 원본 생성 환경과 다를 가능성

## 다음 단계 제안
- 자동 API는 초안/대량 검증용으로만 사용
- 실제 스타일 복제는 `V4.5 웹 UI + 레퍼런스 이미지 + seed 고정` 흐름으로 전환
- 가장 마음에 드는 원본 3~5장만 뽑아 `Vibe Transfer` 중심 재현 테스트를 따로 진행
