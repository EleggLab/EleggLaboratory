# UX 패리티 감사 메모

이 문서는 원본 Expo 모바일 앱 `apps/mobile` 과 토스 앱 `apps/toss` 의 차이를 정리한 메모입니다.

## 자동 감사 기준
- `pnpm audit:parity` 로 아래를 점검합니다.
- 모바일 `assets` 와 토스 `src/legacy/assets` 파일 수 및 해시 비교
- 모바일 `lib` 와 토스 `src/legacy/lib` 파일 수 및 해시 비교
- 주요 화면 파일 7쌍의 diff 규모 집계
- Granite `pages/` 라우트 래퍼 존재 여부 확인

## 현재 확인 결과
- 에셋: 동일 리소스 유지
- 도메인 로직: 누락 파일 없음
- 라우트: `/`, `/today`, `/iching`, `/saju`, `/tarot`, `/tarot/reading`, `/tarot/result` 전부 존재

## 화면별 상태
- 홈: 말풍선, 탭 재선택 초기화, 메인 진입 흐름 유지
- 오늘 운세: 선택, 상세 확인, 탭 재진입 초기화 유지
- 사주: 입력, 저장, 결과, 연운/월운 흐름 유지
- 타로 메인: 카드 선택 진입과 오늘 결과 재확인 흐름 유지
- 타로 리딩: 카드 선택 및 CTA 흐름 유지
- 타로 결과: 결과 카드와 해석 카피 흐름 유지
- 주역: 질문 입력과 결과 확인 흐름 유지

## 의도된 차이
- 상단 헤더와 하단 탭은 토스 셸 구조로 감쌉니다.
- 주요 입력과 버튼은 TDS 컴포넌트로 대체합니다.
- 라우팅과 뒤로가기 처리는 Granite/App-in-Toss 계약에 맞춥니다.

## 남아 있는 판단 포인트
- 화면 구조는 최대한 유지하지만, 토스 검수 친화성을 위해 페이지 크롬은 완전 동일하지 않습니다.
- 콘솔 소개용 기능 설명은 3개 안쪽으로 묶는 편이 안전합니다.
