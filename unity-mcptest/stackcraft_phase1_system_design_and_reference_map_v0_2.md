# StackCraft 기반 소규모 종족 변이/호감도/번식/가계도 게임 설계 v0.2

문서 목적:
- StackCraft 에셋의 공개 기능 범위 안에서 실제 구현 가능한 설계로 정리한다.
- 현재 단계는 건물/집창촌/거점 확장보다 `주인공 2장 + 장소 변이 + 적대 종족 정화 + 호감도 + 자동 생태 + 교배 + 가계도`에 집중한다.
- 이 문서는 사람이 읽는 제안서이면서 동시에 LLM/Codex 계열이 작업 단위로 분해하기 쉬운 명세 문서다.
- 노골적 성행위 묘사는 제외하고, 시스템 레이어를 기준으로 설계한다. 성인 연출은 `IntimacyPresentationLayer`로 분리한다.

---

## 0. 외부 리서치에서 확정한 전제

### 0-1. StackCraft 공개 기능 전제
공개 설명 기준 StackCraft는 다음을 이미 제공하거나 강하게 시사한다.
- 카드 간 상호작용을 제어하는 `Stacking Rules Matrix`
- `Feeding / Selling / Encounters / New Day`로 나뉜 Day Cycle
- 시간 기반 제작 및 발견 시스템
- RPS 전투
- 퀘스트 그룹
- 날짜/랜덤 범위를 이용한 Encounter 스폰
- ScriptableObject 중심의 콘텐츠 추가
- 저장 시스템

따라서 본 프로젝트는 아래 원칙을 따른다.
1. 새 게임 전체를 갈아엎지 않는다.
2. 원래 있는 `Day Cycle + Encounter + SO 데이터 구동`에 기생하듯 확장한다.
3. 새로 만드는 핵심은 `Species/Affection/Reproduction/Genealogy/AutoBehavior` 계층이다.

### 0-2. Stacklands/StackCraft식 구조에서 가져올 것
- 카드가 곧 객체다.
- 카드 상태 변화가 곧 게임의 재미다.
- 상단의 구매/생성원은 원래 카드팩이지만, 본 기획에서는 `고정 장소 카드 슬롯`으로 대체한다.
- 장소 탐험 결과가 자원과 개체 변화를 동시에 만든다.
- 짧은 시간 단위의 처리 + Day 마감 압박은 유지한다.

### 0-3. 이 게임의 차별점
이 게임의 실질 장르는 `카드 스택 생존`이 아니라 아래 조합이다.
- 카드 스택 관리
- 종족 변이 수집
- 선물/호감도 관계 구축
- 자동 생태 관찰
- 혈통/가계도 수집

즉, 플레이어가 건물을 많이 짓는 게임이 아니라 `살아있는 카드 혈통을 키우고 관찰하는 게임`으로 정의한다.

## 1. 제품 포지셔닝

### 1-1. 한 줄 정의
`Stacklands식 카드 관리 위에, 판타지 종족 변이·호감도·혈통 수집을 얹은 소규모 성인 대상 관계 시뮬레이션.`

### 1-2. 플레이 감정 목표
- 처음에는 인간 둘로 시작하는 소규모 생존감
- 장소 카드에 사람을 보내며 새로운 종족을 획득하는 발견감
- 적대 색 카드가 정화되어 동료가 되는 수집감
- 좋아하는 선물을 찾아 관계를 푸는 공략감
- 세대가 이어지며 이름이 누적되는 기록욕
- 자동으로 살아 움직이는 보드를 보는 관찰 재미

### 1-3. 이번 단계에서 의도적으로 제외할 것
- 대규모 건물 테크트리
- 복잡한 경제도시 운영
- 수십 종 이상 종족 확장
- 복잡한 장비 파밍 메타
- 거대한 오픈 월드

### 1-4. 이번 단계 핵심 KPI
- 첫 20분 내 첫 비인간 동료 확보
- 첫 30분 내 첫 호감도 해금
- 첫 45분 내 첫 번식 성공
- 첫 60분 내 가계도 3세대 달성
- 첫 90분 내 적색 종족 정화 2종 이상

## 2. 게임 시작 구조

### 2-1. 시작 카드
필수 시작 카드:
- `ProtagonistMale_Human`
- `ProtagonistFemale_Human`
- `Forest`
- `RockyMountain`
- `Swamp`
- `Sea`
- `CampGround` 또는 매우 단순한 `BaseBoardMarker`
- 기초 선물 루프를 위한 최소 자원 1~2개

### 2-2. 주인공 카드 정의
주인공 2장은 일반 주민과 다르다.

필드:
- 고유 ID
- 이름
- 생물학적 성별: Male/Female
- 기원 종족: Human 고정
- 현재 종족: 변이 가능
- 주인공 플래그: true
- 사망 여부
- 임신 가능 여부
- 교배 가능 여부
- 정화 대상 여부: false
- 가계도 루트 표시 여부: true

### 2-3. 왜 주인공을 일반 카드와 분리하는가
- 플레이어가 감정적으로 붙잡을 대상이 필요하다.
- 변이되더라도 “내 시작 카드”라는 서사가 유지되어야 한다.
- 가계도 루트의 기준이 필요하다.
- 자동 교배를 지나치게 허용하면 플레이어 개입의 의미가 줄어든다.

권장 규칙:
- 주인공 카드는 자동 교배 비활성화 가능 옵션 제공
- 기본값은 `주인공은 플레이어가 직접 행동시킬 때만 교배` 권장

## 3. 코어 루프

### 3-1. 30초~2분 단위 마이크로 루프
1. 장소 카드를 확인한다.
2. 인간 또는 특정 종족 카드를 장소에 배치한다.
3. 타이머가 진행된다.
4. 결과로 자원, 적, 변이 카드, 이벤트가 나온다.
5. 선물을 모은다.
6. 동료/정화된 종족에게 선물을 준다.
7. 호감도를 올린다.
8. 호감도 임계값 달성 시 짝짓기 가능 상태를 연다.
9. 교배를 시작하면 일정 시간 두 카드는 잠긴다.
10. 결과 카드(임신 상태/알/신생아/유아)가 나온다.
11. 개체는 이름과 혈통을 가진 새 카드로 편입된다.

### 3-2. 1일 단위 메타 루프
1. Day 시작
2. 장소 탐사/전투/정화/선물 루프 수행
3. 저녁에 Feeding phase 처리
4. 진행 중인 임신/교배/성장 타이머 감소
5. Encounter phase에서 적색 종족/이벤트 스폰
6. New Day로 이동하며 특정 장소 산출물/상태 갱신

### 3-3. 장기 루프
- 인간 기원 개체를 다양한 장소에 보내 종족 폭을 넓힌다.
- 적색 적대 종족을 전투로 정화하여 새로운 혈통 가지를 해금한다.
- 종족별 선호 선물을 파악해 호감도 상승 효율을 최적화한다.
- 특정 종족 조합에서만 나오는 하이브리드/변이 자손을 수집한다.
- 가계도에서 희귀 혈통을 모은다.

## 5. 장소 시스템 설계

### 5-1. 공통 장소 규칙
장소 카드는 기본적으로 두 역할을 가진다.
- `탐색 자원 산출기`
- `인간/특정 종족 변이기`

기본 처리 함수:
- 인간 기원 개체가 올라감 → 일정 시간 후 해당 장소 계열 종족 또는 자원으로 결과 생성
- 비인간 개체가 올라감 → 채집/사냥/탐색 결과만 생성, 변이는 기본적으로 없음
- 특정 종족만 예외적으로 상위 변이 가능

### 5-2. 숲
테마:
- 생명, 우아함, 교감, 식물성 선물

인간 파견 결과 예시:
- 엘프
- 하프엘프 성향 변이 씨앗
- 꽃
- 허브
- 열매
- 버섯
- 목재

선물 루프:
- 엘프 계열이 꽃/허브를 선호
- 일부 숲 계열은 열매를 선호

### 5-3. 바위산
테마:
- 힘, 체격, 거친 성향, 광물

인간 파견 결과 예시:
- 드워프 또는 산악계 인간 변이
- 오우거 관련 적색 Encounter 확률 상승
- 광석
- 돌
- 뿌리채소
- 단단한 뼈

선물 루프:
- 체격형 종족은 고기/뿌리채소/술 유사 아이템 선호 가능
- 이번 단계에서는 술은 제외하고 고기/당근/뿌리열매로 단순화

### 5-4. 늪
테마:
- 독성, 타락, 야성, 변이

인간 파견 결과 예시:
- 리자드계 / 늪요정 / 점액계 전초 변이
- 오크 적색 Encounter 확률 상승
- 버섯
- 늪꽃
- 진흙
- 독샘플

선물 루프:
- 늪/야성 계열은 고기, 희귀 버섯, 강한 냄새 자원 선호

### 5-5. 바다
테마:
- 유동성, 매혹, 이질성, 진주성 자원

인간 파견 결과 예시:
- 머메이드/해양계 변이
- 켄타우로스 대신 바다 계열이면 방향성 흔들리므로, 1차에서는 `해양 이종족` 1종만 권장
- 조개
- 진주
- 물고기
- 해초

선물 루프:
- 해양계는 진주/생선/해초 선호

### 5-6. 장소별 결과 구조 권장
모든 장소에 대해 아래 형식으로 데이터화:

```yaml
LocationData:
  id: Forest
  biomeTag: Nature
  explorationTimeSec: 40
  mutationEnabledForOriginSpecies:
    - Human
  mutationTable:
    - resultSpecies: Elf
      weight: 35
    - resultSpecies: ForestTouchedHuman
      weight: 20
  lootTable:
    - item: Flower
      weight: 25
    - item: Herb
      weight: 20
    - item: Carrot
      weight: 10
  encounterTable:
    - encounterId: ForestEnemyMinor
      weight: 10
```

## 6. 종족 구조

### 6-1. 이번 단계 권장 최소 종족 수
시작 시점 총 7~8종 권장.

플레이어 기원/변이 가능:
- Human
- Elf
- Dwarf(선택)
- Marshkin 또는 Lizardfolk(선택)
- Seaborn(선택)

적색 적대 상태로 먼저 등장:
- Orc
- Ogre
- Centaur

초기 스코프를 더 줄이려면 6종으로 시작:
- Human
- Elf
- Seaborn
- Orc
- Ogre
- Centaur

### 6-2. 종족 정의 필드

```yaml
SpeciesData:
  id: Orc
  defaultCardColor: Red
  faction: DemonicOrHostile
  bodyType: Large
  giftPreferenceProfile: MeatHeavy
  canAutoBreed: true
  canBreedWith:
    - Orc
    - Human
    - Elf
  hostilityDefault: Hostile
  purificationRequired: true
  purifiedColor: Neutral
  offspringPoolRules:
    sameSpecies: Orc
    crossSpeciesTable: OrcHybridTable_A
```

### 6-3. 카드 색의 의미
- 베이지/기본색: 중립/아군/교배 가능 후보
- 적색: 적대, 호감도 불가, 선물 반응 없음, 플레이어 직접 소유 불가
- 회색: 임신/교배/회복 등으로 잠김
- 금색 테두리: 주인공 또는 희귀 혈통

### 6-4. 적색 정화 규칙
- 적색 오크/오우거/켄타우로스는 Encounter로 등장
- 전투에서 승리하면 `Purified` 상태가 된다
- 정화 즉시 카드 색이 기본색으로 전환된다
- 그 시점부터 선물 가능, 호감도 상승 가능, 교배 가능
- 정화 전투가 곧 해당 종족 해금 수단이다

### 6-5. 플레이 경험 관점의 중요성
이 규칙은 중요하다.
- 적색 상태는 “전투 컨텐츠”다.
- 정화 후 상태는 “관계/혈통 컨텐츠”다.
- 같은 캐릭터 타입이 전투와 관계 루프 둘 다 담당하므로 콘텐츠 효율이 높다.

## 7. 호감도 시스템

### 7-1. 설계 목표
- 교배 전에 반드시 관계 해금 과정을 넣는다.
- 선물 조합을 찾는 재미를 만든다.
- 종족별 성격 차이를 자원 선호도로 표현한다.
- 플레이어가 장소 탐험과 관계 공략을 연결하도록 만든다.

### 7-2. 호감도 기본 규칙
- 호감도 대상은 `인간 남성 외의 캐릭터`로 우선 설계한다는 유저 아이디어를 반영 가능
- 더 확장하면 모든 개체에 적용 가능
- 현재 단계에서는 보수적으로 `주인공 남성 -> 타 대상`, `주인공 여성 -> 타 대상`, `동료끼리 내부 친밀도`의 3축으로 나눔

권장 1차 구현:
- 플레이어 선물 행동으로 직접 올리는 `Affinity`
- NPC끼리 천천히 누적되는 `Bond`

### 7-3. 단계 구조
예시:
- 0~19: 무관심
- 20~39: 인지
- 40~59: 친밀
- 60~79: 우호
- 80~99: 깊은 유대
- 100: 교배 해금

### 7-4. 상승 조건
- 선물 제공
- 특정 장소 동행 성공
- 전투에서 구출/정화
- 이벤트 선택지 성공

### 7-5. 하락 조건
- 비선호 선물 제공
- 굶주림/방치
- 전투 패배로 인한 공포 상태
- 장기간 미상호작용

### 7-6. 선물 선호 프로필 예시

```yaml
GiftPreferenceProfile:
  Elf:
```

## 8. 자동 행동 AI

### 8-1. 왜 필요한가
사용자가 명시한 핵심: `인간 외 생물들은 알아서 움직이고 같은 종 남녀끼리는 알아서 교배도 한다`.
이건 게임을 살아 있게 만드는 핵심이다.

### 8-2. AI 상태기계 최소 버전

상태:
- Idle
- Wander
- SeekGiftLikeResource
- SeekMate
- BreedLocked
- Recover
- Hungry
- FleeOrFight

### 8-3. 자동 행동 규칙
- 비주인공 개체만 자동 이동
- 같은 종/이성/성체/호감도 조건 충족 시 `SeekMate`
- 교배가 시작되면 두 카드 모두 `BreedLocked`
- Locked 동안 플레이어 드래그 불가
- Hungry 상태면 교배보다 생존 행동 우선

### 8-4. 자동 교배 균형장치
필수 밸런스 장치:
- 자동 교배 내부 쿨다운
- 번식 슬롯 제한
- 과밀 패널티
- 출산 후 회복 디버프
- Day 당 자동 교배 최대 횟수 제한

### 8-5. 권장 수치
- 자동 교배 시도 최소 호감도: 65
- 플레이어 직접 교배 최소 호감도: 50 또는 60
- 자동 교배 재시도 쿨다운: 1~2일
- 출산 후 회복: 1일
- 보드 전체 자동 임신 최대치: 2~3

이렇게 해야 보드가 자동 번식으로 폭주하지 않는다.

## 9. 교배/임신/출산 시스템

### 9-1. 원칙
- 교배는 즉시 보상이 아니라 `시간 투자`다.
- 진행 중에는 카드를 못 건드린다.
- 결과는 개체 수 증가이자 혈통 정보 추가다.

### 9-2. 단계
1. Pairing 시작
2. `BreedLocked` 진행 바 노출
3. 완료 시 `Pregnancy` 또는 `Egg/Brood` 상태 생성
4. Day 경과 혹은 시간 경과
5. 출생
6. 성장
7. 성체화

### 9-3. 표현 방식 옵션
옵션 A: 임신 카드 방식
- 수태한 캐릭터가 `Pregnant` 태그를 가짐
- 일정 시간 후 아이 카드 생성

옵션 B: 알/고치 카드 방식
- 하이브리드/비인간계에 더 어울림
- 부모 잠금 종료 후 별도 `BroodCard` 생성
- 부화 시간 관리가 쉬움

권장:
- 인간/인간형은 Pregnancy
- 일부 종족 조합은 Egg/Brood

### 9-4. 출생 결과
새 카드 필드:
- uniqueId
- displayName
- sex
- originSpeciesA
- originSpeciesB
- currentSpecies
- fatherId
- motherId
- generation
- inheritedTraits[]
- mutationTags[]
- genealogyNodeId

### 9-5. 남남/여여 규칙
명시적으로 비활성화.
- 관계도는 가능
- 교배는 불가
- UI에서도 애매하게 보이지 않도록 `Breeding Not Available` 명확 표기

### 9-6. 친족 규칙
이번 단계 권장:
- 근친 금지 또는 매우 강한 패널티 중 하나 선택
- 대중성과 제작 리스크를 고려하면 `직계/형제 근친 금지` 권장

필터:
- 부모-자식 금지
- 형제/자매 금지
- 조부모-손자 금지

## 10. 유전/자손 결정 시스템

### 10-1. 너무 복잡하게 시작하지 않는다
Niche 수준의 실제 유전학 시뮬레이션은 초반 범위를 망친다.
1차는 `가중치 기반 형질 상속`이 가장 적절하다.

### 10-2. 자손 결과 결정 레이어
- 레이어 A: 기본 종족 결정
- 레이어 B: 외형 태그 결정
- 레이어 C: 성향/보너스 태그 결정
- 레이어 D: 희귀 돌연변이 판정

### 10-3. 종족 결정 권장 방식
동종 교배:
- 부모 종족 그대로 85~95%
- 희귀 상위/아종 변이 5~15%

이종 교배:
- 부모 A 종족 35%
- 부모 B 종족 35%
- 하이브리드 20%
- 희귀 변이 10%

이 값은 종족별 테이블로 다르게 정의 가능.

### 10-4. 특성 태그 예시
- Strong
- Graceful
- Fertile
- Wild
- Calm
- Swift
- LargeFrame
- ForestBorn
- SwampTouched
- PureLineage

### 10-5. LLM 친화 데이터 구조 예시

```yaml
OffspringRuleSet:
  id: Human_Orc
  allowed: true
  resultTable:
    - species: Human
      weight: 30
    - species: Orc
      weight: 30
    - species: HalfOrc
      weight: 30
    - species: RareMutant_HumanOrc_A
      weight: 10
  inheritedTraitPools:
    dominant:
      - Strong
      - Wild
    recessive:
      - Calm
      - Fertile
  pregnancyType: Pregnancy
  minimumAffinity: 60
```

### 10-6. 성장 단계
- Infant
- Child
- Adult

초기 버전 단순화:
- Infant는 보드 관리 부담 큼
- Child -> Adult 2단계만 먼저 구현하는 편이 낫다

권장:
- 출생 시 `Young`
- 1~2일 후 `Adult`

## 11. 전투와 적색 종족 해금

### 11-1. 적 등장 규칙
원작처럼 일정 시간/일차별 등장.
- Day 2 이후 오크 소규모 등장
- Day 4 이후 켄타우로스
- Day 6 이후 오우거

### 11-2. 적 등장 위치
- Encounter phase에서 보드 가장자리
- 또는 특정 장소 탐사 시 확률 스폰

### 11-3. 전투 결과 분기
- 패배: 부상/자원 손실/호감도 하락
- 승리: 자원 드랍 + 정화 판정

### 11-4. 정화 판정
기본 권장:
- 일반 적 처치 70% 제거, 30% 정화
- 특수 스킬/아이템 사용 시 정화 확률 상승
- 보스형은 전용 이벤트로 100% 정화 보장 가능

### 11-5. 정화 보상 설계 의도
- 단순 처치보다 정화가 더 좋은 결과를 주면 플레이어가 사냥보다 회수/편입을 선호하게 된다.
- 이 선택이 전투 루프와 혈통 루프를 잇는다.

## 12. 카드 상세 보기와 가계도

### 12-1. 이 시스템은 필수다
유저가 명시한 `모든 카드는 자세히 볼 수 있고 지금까지의 가계도가 쭉 나오도록`을 핵심 요구사항으로 고정한다.

### 12-2. 카드 상세 정보
필수 표시:
- 카드 아트 크게
- 이름
- 성별
- 현재 종족
- 기원 종족
- 카드 색 의미
- 호감도 수치/단계
- 선호 선물
- 생애 상태
- 부모
- 자식 수
- 세대 번호
- 대표 형질
- 등장/정화/출생 로그

### 12-3. 이름 시스템
모든 개체는 이름을 가져야 한다.

권장 규칙:
- 종족별 이름 풀
- 플레이어 수동 개명 허용
- 자동 이름은 `이름 + 종족 접미`보다 자연어 이름 우선

예시:
- 인간: 이안, 마라
- 엘프: 엘리아, 세린
- 오크: 고르, 바르카
- 켄타우로스: 카엘, 리오네

### 12-4. 가계도 데이터 구조

```yaml
GenealogyNode:
  entityId: npc_00124
  displayName: Serin
  sex: Female
  currentSpecies: Elf
  generation: 2
  fatherId: npc_00001
  motherId: npc_00007
  childrenIds:
    - npc_00201
    - npc_00208
  partnerHistory:
    - npc_00032
  statusFlags:
    - Purified
    - RareTrait
```

### 12-5. 가계도 UI 모드
- 전체 트리
- 선택 카드 기준 위/아래 2세대 집중 보기
- 종족 필터
- 희귀 혈통 하이라이트
- 정화 계열 하이라이트

### 12-6. 도감과 가계도 분리
- 도감 = 종족/아이템/조합 지식
- 가계도 = 실제 플레이에서 태어난 개체의 역사

둘을 분리해야 수집 욕구가 길게 간다.

## 13. 밸런스 가이드

### 13-1. 폭주를 막는 핵심
가장 큰 위험은 번식 폭주다.
아래 네 가지를 동시에 써야 한다.
- Feeding 비용
- 임신/회복 시간
- 보드 최대 인구 소프트캡
- 호감도 요구치

### 13-2. 인구 소프트캡
권장:
- 8장 이하: 안정
- 9~12장: 먹이 압박 상승
- 13장 이상: 자동 호감도 감소/스트레스/질병 확률 증가

### 13-3. 선물 경제 밸런스
- 좋아함: +8
- 매우 좋아함: +12
- 보통: +3
- 싫어함: -5
- 매우 싫어함: -10

권장 호감도 요구치:
- 첫 대화/관심: 20
- 소형 이벤트: 40
- 교배 가능: 60
- 자동 교배 활성: 70

### 13-4. 장소 리스크/보상
- 숲: 안전, 저위험, 저중보상
- 바위산: 자원 좋음, 전투 위험 중간
- 늪: 희귀 변이/오염 자원, 위험 높음
- 바다: 희귀 선물, 시간 다소 김

### 13-5. 정화 밸런스
정화된 적색 종족은 강하지만 공략 비용이 들도록 한다.
예시:
- 오크: 호감도 상승 난이도 중
- 켄타우로스: 선호 선물 찾기 쉬움, 정화 난이도 중상
- 오우거: 전투/먹이 부담 큼, 관계 속도 느림

## 14. UX/UI 설계 포인트

### 14-1. 카드 상태의 시각 분리
카드에서 한눈에 보이게 해야 하는 상태:
- 적대
- 정화됨
- 호감도 가능
- 교배 가능
- 임신/잠금
- 배고픔
- 희귀 혈통

### 14-2. 아이콘 계층
카드 우상단 소형 아이콘:
- 하트: 호감도 단계
- 자물쇠: 교배 중/잠금
- 혈통나무: 가계도 중요 카드
- 칼: 적대

### 14-3. 드래그 피드백
- 장소 위에 인간 카드 올릴 때: 변이 가능 여부 하이라이트
- 선물 카드 올릴 때: 좋아함 예측 색상
- 교배 가능한 두 카드 근접 시: 하트 윤곽선
- 불가 조합 시: 회색 X 표시

### 14-4. 로그 시스템

- `세린이 꽃을 좋아했습니다 (+12)`

- `이안과 세린이 유대를 맺었습니다`
- `새로운 혈통: 하프오크가 태어났습니다`

### 14-5. 카드 확대 뷰
확대 시 필수 탭:
- 개요
- 관계
- 혈통
- 선물
- 기록

## 15. 성인 연출 레이어 처리 원칙

### 15-1. 시스템과 연출을 분리한다
핵심 구현 순서는 아래가 맞다.
1. 호감도
2. 교배 가능 판정
3. 진행 시간 잠금
4. 결과 카드 생성
5. 이후에만 연출 레이어 연결

### 15-2. 이유
- 검증 가능한 핵심은 시스템이다.
- 연출은 교체 가능하지만 시스템은 골격이다.
- MCP/LLM으로 구현할 때도 시스템 분해가 훨씬 쉽다.

### 15-3. 데이터 분리 예시

```yaml
IntimacyPresentationLayer:
  enabled: true
  sceneSetBySpeciesPair:
    - Human_Elf
    - Human_Orc
    - Human_Centaur
  durationSec: 12
  blocksInput: true
  completionTriggers:
    - applyBreedLock
    - spawnPregnancyOrBrood
```

즉, 성인 연출은 코어 규칙을 건드리지 않는 `플러그인 레이어`로 둔다.

## 16. 유사 게임 조사와 차용 포인트

### 16-1. Stacklands / StackCraft 계열
차용 포인트:
- 카드=객체라는 강한 추상화
- 장소 탐험 기반 자원 회수
- 일 단위 생존 압박
- 데이터 주도 확장성

이 프로젝트에서 차용할 핵심:
- 장소 카드를 성장 루프의 시작점으로 삼기
- 복잡한 월드 대신 카드 상태 변화로 콘텐츠를 전달하기
- SO 기반 데이터 드리븐 콘텐츠 설계

### 16-2. Niche
왜 보나:
- 종족/세대/유전/생존을 매우 잘 연결한 대표작

차용 포인트:
- 혈통 관리가 곧 전략이 되는 구조
- 세대가 이어질수록 수집과 최적화가 동시에 발생
- 살아남는 종과 도태되는 종의 서사화

이 프로젝트에선 이렇게 번역:
- 실제 유전학 대신 `희귀 형질 태그`와 `가계도`를 핵심 재미로 둔다
- 혈통이 쌓일수록 희귀 조합 해금률을 높인다

### 16-3. RimWorld Biotech
왜 보나:
- 가족/아이/유전자/콜로니 운영을 한 시스템으로 엮는 데 매우 강함

차용 포인트:
- 가족 생성이 단순 숫자 증가가 아니라 스토리 생성이 되게 함
- 임신/양육/성장 단계를 별도 시스템으로 분리
- 유전과 성장 이벤트를 메타 목표로 연결

이 프로젝트에선 이렇게 번역:
- 아이를 바로 성체로 두지 말고 최소한 성장 단계를 둔다
- 혈통 카드의 장기 가치가 생기게 한다

### 16-4. Ova Magica
왜 보나:
- 친밀도, 돌봄, 브리딩, 개체 수집을 귀엽고 읽기 쉬운 UX로 묶음

차용 포인트:
- 브리딩 전 준비 아이템/관계 단계
- 개체 보관/관리의 단순한 흐름
- 색/특징/스킬이 자손에게 이어지는 조합 재미

이 프로젝트에선 이렇게 번역:
- Heart Fruit 같은 전용 아이템 대신 `선호 선물 + 호감도 임계값`으로 간소화
- 개체 상세/특성 확인 UX를 잘 보여줘야 함

### 16-5. The Monster Breeder
왜 보나:
- 최근작 중 종 교배 + 형질 관리 + 전투 보상을 함께 묶은 케이스

차용 포인트:
- 교배가 전투용 강자 생산과 직접 연결됨
- 하이브리드 생산이 엔드게임 동기 부여가 됨

이 프로젝트에선 이렇게 번역:
- 적색 적대 종족을 정화해 혈통으로 편입하는 메타를 강조
- 단순 도감 수집이 아니라 “강한 혈통” 목표도 둘 수 있음

### 16-6. Beast Breeder / Corruption Ranch / Breeders of the Nephelym 같은 성인 틈새작
왜 보나:
- 성인 시장에서 실제로 먹히는 건 `관계 + 브리딩 + 관리`의 결합임
- 단순 씬 수집보다 `개체 수집/조합/관리`가 반복 플레이를 만든다

차용 포인트:
- 몬스터/종족 조합으로 새 개체를 만드는 장기 목표
- 성인 테마가 코어 시스템 위에 얹힐 때 유지력이 생김

이 프로젝트에서의 결론:
- 성인 게임이더라도 중심은 `관계-번식-혈통-수집`이어야 한다.
- 노골적 장면 자체를 코어 루프로 삼으면 반복플레이가 약해진다.

## 22. 최종 권고

지금 당장 가장 좋은 방향은 다음이다.

1. 종족을 적게 시작한다.
2. 카드팩을 장소 카드로 대체한다.
3. 적색 적대 종족을 전투-정화-편입 구조로 묶는다.
4. 선물 호감도 없이는 번식이 열리지 않게 한다.
5. 자동 생태는 비주인공 카드에 제한적으로 적용한다.
6. 모든 개체에 이름/혈통/세대 기록을 남긴다.
7. 성인 연출은 시스템 뒤에 붙는 프레젠테이션 레이어로 분리한다.

이렇게 하면 개발 범위가 통제되고, 카드 게임으로서도 재밌고, 성인 게임으로서도 반복 플레이 동기가 생긴다.
