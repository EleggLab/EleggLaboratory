# 추가 자료 조사 플랜 (광범위)

업데이트: 2026-03-14

## 조사 목적
- `starter/` 고도화에 직접 반영 가능한 자료만 수집
- "읽기 좋은 링크 모음"이 아니라 "바로 적용 가능한 패턴" 중심

## 조사 축 (6개)
1. **에이전트 코딩 워크플로우**
   - 계획→실행→검증 루프, 실패 복구 패턴
2. **프롬프트 엔지니어링(코드 생성 특화)**
   - System/Task/Review 프롬프트 분리 전략
3. **컨텍스트 엔지니어링**
   - 대형 레포에서 컨텍스트 축소/선택 전략
4. **품질 자동화**
   - 테스트/린트/정적분석/보안 스캔 조합
5. **다국어 문서화**
   - 용어집 기반 번역 워크플로우, README 동기화
6. **실전 샘플 프로젝트**
   - 웹앱/봇/CLI에서 재사용 가능한 최소 골격

## 언어/채널 범위
- 1순위: English, 한국어, 中文, 日本語
- 2순위: Español, Português, العربية, Русский
- 소스 채널: GitHub, 공식 문서, 기술 블로그, 컨퍼런스 슬라이드

## 수집 단위 (카드 기반)
각 자료를 아래 포맷으로 저장:
- 제목
- 링크
- 핵심 패턴 3줄
- starter 반영 위치 (예: `prompts/`, `scripts/`, `checklists/`)
- 신뢰도 (높음/중간/낮음)

## 산출물 계획
- `research/cards/*.md` : 개별 자료 카드
- `research/synthesis-week1.md` : 1차 종합 리포트
- `starter/backlog.md` : 반영할 작업 백로그

## 주간 실행안 (Week 1)
- Day 1: 에이전트 워크플로우 + 프롬프트
- Day 2: 컨텍스트 엔지니어링 + 품질 자동화
- Day 3: 다국어 문서화 + 샘플 프로젝트
- Day 4: 중복 제거/우선순위 재정렬
- Day 5: starter 반영 PR 묶음 생성

## 성공 기준
- 적용 가능한 패턴 20개 이상 확보
- starter에 실제 반영 가능한 항목 10개 이상 선별
- low-confidence 자료 비율 20% 이하 유지
