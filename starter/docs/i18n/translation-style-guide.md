# Translation Style Guide (Starter)

## Core Rules
- Keep code blocks, file paths, commands unchanged.
- Preserve product names and technical terms.
- If no exact translation, keep original in parentheses.
- Do not alter semantic strength (must/should/may).

## Tone by Locale
- ko: 간결하고 단정한 실무 톤
- en: direct, actionable, low-fluff
- ja: 丁寧だが冗長하지 않게
- zh: 简明、结构化、可执行

## Terminology Policy
- Maintain glossary first; avoid free-form synonym drift.
- Prefer consistency over literary style.

## QA Checklist
- Meaning parity
- Command/path integrity
- Terminology consistency
- Readability in target locale
